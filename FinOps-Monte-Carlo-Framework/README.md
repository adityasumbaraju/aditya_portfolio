# FinOps Monte Carlo Framework

[![Tests](https://github.com/adityasumbaraju/aditya_portfolio/actions/workflows/tests.yml/badge.svg)](https://github.com/adityasumbaraju/aditya_portfolio/actions/workflows/tests.yml)

A Monte Carlo simulation framework for evaluating multi-cloud data pipeline investment decisions under correlated uncertainty. Companion reference implementation for the manuscript *"Integrating Predictive Demand Analytics into Multi-Cloud Data Pipelines: A Monte Carlo Framework for Enterprise Investment Decisions"* by Aditya Sumbaraju, prepared for submission to IEEE Access.

> **Status:** Manuscript in preparation for submission to IEEE Access. This repository contains the reference implementation used to generate all results reported in the manuscript. Parameter values are illustrative calibrated assumptions for a reproducible example, not proprietary production data.

## Key Results (Table V)

10,000 iterations, 8% WACC, 3-year NPV horizon.

| Scenario | Mean ROI | SD (pts) | P(ROI > 8%) |
|----------|----------|----------|-------------|
| A: Capacity Expansion | 14.5% | 6.9 | 83.3% |
| B: ETL Automation | 10.8% | 2.1 | 93.5% |
| C: Governance Tooling | 9.5% | 4.1 | 60.7% |

The probabilistic ranking (B > A > C by probability of clearing the 8% WACC threshold) differs from the mean-ROI ranking (A > B > C). This reranking is the central finding of the manuscript and is confirmed stable across Student-t copula, independence, and data-quality-degradation perturbations, and in 100 of 100 bootstrap resamples.

## How to Run and Replicate Results

All results in the manuscript are generated by running five scripts in order. Each script is self-contained, reuses the same calibrated parameters from `config/params_config.json` and the same simulation engine, and prints a console summary plus writes a machine-readable output file. The random seed is fixed (`42`), so re-running reproduces the published numbers exactly.

### Prerequisites

- Python 3.9 or newer (developed on 3.14)
- A POSIX shell (Linux, macOS, or WSL on Windows)
- ~50 MB of free disk for outputs and figures

### Step 1 — Install dependencies

```bash
pip install -r requirements.txt
```

This installs NumPy, SciPy, Pandas, and Matplotlib — the only third-party packages required. (The PDF manuscript is pre-built in this repo as `Manuscript_IEEE_Access_Revised.pdf`; rebuilding it additionally requires `reportlab`, installed via `pip install reportlab`.)

### Step 2 — Run the full replication sequence

From the repository root, run the five scripts in order. Each takes a few seconds:

```bash
python main.py                  # Tables V and VII
python sensitivity_analysis.py # Table VI
python generate_figures.py     # Figures 1 and 2
python decision_experiment.py  # Table VIII
python reviewer_fixes.py      # Table IX and Sections IV-J to IV-M
```

### Step 3 — Verify the console output

Each script prints a summary you can check against the manuscript. The key checkpoints:

**`main.py` — Table V (ROI distributions) and Table VII (tail-risk metrics):**
```
Scenario        Mean ROI    SD (pts)     5th pct    95th pct   P(ROI>8%)
A                  14.5%        6.9        4.7%       27.1%       83.3%
B                  10.8%        2.1        7.8%       14.6%       93.5%
C                   9.5%        4.1        3.7%       17.0%       60.7%

Ranking by mean ROI:        A > B > C
Ranking by P(ROI > 8%):    B > A > C
Reranking under probabilistic rule: YES
```
The mean ranking (A>B>C) differs from the threshold-exceedance ranking (B>A>C) — this is the reranking effect at the heart of the paper.

**`sensitivity_analysis.py` — Table VI (robustness):** confirms the B>A>C ordering holds under independent sampling, a Student-t copula (df=5), and 10%/25% correlation degradation. It also prints `B overtakes A in 100 of 100 bootstrap resamples`.

**`decision_experiment.py` — Table VIII (threshold-criterion recovery):** the probabilistic rule recovers the true P(ROI>8%) winner in 99% of trials versus 0% for the deterministic mean-ROI rule. Prints a `NOTE: synthetic DGP, not an empirical backtest` reminder.

**`reviewer_fixes.py` — Table IX and Sections IV-J to IV-M (reviewer fixes):** prints the threshold sweep table. Verify the crossover line: `Reranking crossover threshold: 10.0%` (the B>A reranking holds below 10% and inverts at 10%). Also confirms: prevalence 2.6%, de-circularized recovery 93.9% vs 10.8%, and break-point at 1.5x mean-preserving variance.

### Step 6 — Run the automated test suite

The repository includes a pytest suite that reruns the full simulation pipeline and asserts every published table value reproduces, guarding against regressions (including the two logic bugs caught during review — the de-circularized recovery inversion and the non-mean-preserving break-point).

```bash
pip install -r requirements-dev.txt
pytest -q
```

The suite runs all five scripts once (via a session-scoped fixture), then asserts against the freshly generated `outputs/*.json` files:

| Test group | Verifies | Manuscript artifact |
|-----------|----------|----------------------|
| `TestTableV` | mean/SD/P(ROI>8%) per scenario | Table V |
| `TestReranking` | mean ranking A>B>C, threshold ranking B>A>C | Section IV-C |
| `TestTableVII` | B highest VaR/CVaR, lowest downside | Table VII |
| `TestTableVI` | B>A>C under all copula/degradation conditions; bootstrap 100/100 | Table VI |
| `TestTableVIII` | probabilistic recovery 99%, deterministic 0% | Table VIII |
| `TestTableIX` | crossover at 10%, B>A below 10%, inverts at ≥10% | Table IX |
| `TestPrevalence` | A/B-type reranking incidence 2.6% | Section IV-J |
| `TestDecircularizedRecovery` | probabilistic 93.9% vs deterministic 10.8%; guards against the corrected inverted-logic bug | Section IV-K |
| `TestCorrelationSensitivity` | B>A across rho 0.0-0.8 | Section IV-L |
| `TestBreakPoint` | mean-preserving break at 1.5x; mean held fixed across sweep | Section IV-M |

Tolerances are ±0.1 percentage point on Monte Carlo probabilities (the seed is fixed, so results are deterministic up to tiny numerical differences across NumPy/SciPy versions); exact equality is used for ranking strings, the 10% crossover, the bootstrap count, and the break-point multiplier. All 34 tests should pass on a clean run.

The same sequence runs automatically on GitHub Actions (`.github/workflows/tests.yml`) on every push and pull request to `main`, so regressions are caught before merge.

### Reproducibility notes

- **Fixed seed:** the simulation seed is set to `42` in `config/params_config.json` (`simulation.random_seed`). Re-running with the same seed reproduces the published numbers exactly; changing the seed produces Monte Carlo variation of roughly ±0.3 percentage points on the P(ROI>8%) values.
- **Single source of truth:** all parameters — distributions, the 5×5 correlation matrix, scenario benefit components, the 8% WACC, and the 3-year horizon — live in `config/params_config.json`. Edit that one file to change inputs; no code changes are required.
- **No external data required:** the framework runs entirely on the calibrated illustrative parameters. To replace them with real telemetry, follow the four-step calibration workflow below; the script fails gracefully (prints the required schema) if no telemetry file is supplied and does not fabricate synthetic parameters.

## Empirical Calibration (replacing illustrative assumptions with telemetry)

All parameter distributions in `config/params_config.json` are illustrative calibrated assumptions for a reproducible example. To calibrate empirically:

1. Collect telemetry matching the schema in `calibration/telemetry_schema.md` (at least one full seasonal cycle: records/day, per-record unit cost, utilization, throughput, compute cost per record, plus optional governance and scenario-benefit columns).
2. Run `python calibration/fit_from_telemetry.py --csv telemetry.csv` to fit marginals from observed telemetry, estimate the dependence matrix (Spearman rank correlation for the Gaussian copula), and report a Kolmogorov-Smirnov goodness-of-fit statistic per variable.
3. Compare the Gaussian copula against the Student-t (and vine/empirical where data support it) using the goodness-of-fit evidence.
4. Replace the fixed and demand-linked benefit components with finance- or operations-derived estimates (these are not fitted from operational telemetry alone — see the schema).

The calibration script fails gracefully when no telemetry is supplied and does **not** fabricate synthetic "empirical" parameters. The decision experiment (`decision_experiment.py`) uses a synthetic data-generating process and is **not** an empirical backtest. The reviewer-fix analyses (`reviewer_fixes.py`) explicitly test the limits of the paper's own claims: the threshold sweep shows the B>A reranking inverts at a 10% hurdle rate; the prevalence sweep finds A/B-type reranking in only 2.6% of draws from an illustrative prior; the de-circularized recovery experiment (independent prior, not the paper's calibrated values) confirms the probabilistic rule recovers the true threshold-exceedance winner in 93.9% of reranking cases versus the deterministic rule's 10.8%, showing the recovery advantage survives removal of the original circularity; and a mean-preserving variance widening of 1.5x on B flips the ranking, confirming the reranking is variance-driven and falsifiable.

## Repository Structure

- `main.py` - master simulation runner (Table V + tail-risk metrics Table VII)
- `sensitivity_analysis.py` - correlation/data-quality robustness + bootstrap
- `generate_figures.py` - manuscript figures
- `decision_experiment.py` - synthetic threshold-criterion recovery experiment (Table VIII, synthetic DGP)
- `reviewer_fixes.py` - skeptical-reviewer fixes: threshold-sensitivity sweep (Table IX), parameter-prevalence sweep, de-circularized recovery experiment, correlation-matrix sensitivity, and break-point analysis (Sections IV-I through IV-M)
- `calibration/telemetry_schema.md` - required telemetry fields to replace illustrative assumptions
- `calibration/fit_from_telemetry.py` - fits marginals/correlations from observed telemetry
- `scenarios/scenario_{a,b,c}.py` - scenario ROI equations
- `utils/copula.py` - Gaussian and Student-t copula sampling
- `config/params_config.json` - all distributions, correlations, and calibrated parameters
- `outputs/` - simulation results (CSV, JSON). This is the only results directory; `main.py` and `sensitivity_analysis.py` both write here. (An older draft used a `results/` folder — it is unused and can be deleted.)
- `figures/` - manuscript figures
- `tests/` - pytest suite (`test_manuscript_results.py`, `conftest.py`) that reruns all scripts and asserts every published table value reproduces
- `pytest.ini` - pytest configuration
- `requirements-dev.txt` - test dependencies (pytest)
- `.github/workflows/tests.yml` - GitHub Actions CI: installs dependencies, runs all five result scripts, then executes the pytest suite on every push and pull request

## Financial Model

ROI is NPV-based: `ROI = (AnnualBenefit × annuity_factor − Investment) / Investment`, where the annuity factor at 8% WACC over 3 years is 2.577. The decision threshold is the 8% WACC. Each scenario's annual benefit combines a fixed (volume-invariant) component and a demand-linked component scaled to annual cloud spend, which carries the copula correlation structure and gives each scenario a distinct, economically defensible variance.
